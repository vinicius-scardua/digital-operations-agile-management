# Kanban Workflow — Digital Operations

## 1. Purpose

This document describes the Kanban workflow designed for the simulated Digital Operations project.

The objective is to organize operational activities, visualize work progress, manage priorities, and support continuous improvement.

## 2. Workflow Structure

The Jira Kanban board uses five workflow stages:

| Column | Description |
|---|---|
| Idea | Activities identified but not yet prioritized for execution |
| To Do | Prioritized activities ready to be started |
| In Progress | Activities currently being executed |
| Testing | Activities under review or validation |
| Done | Activities completed according to their requirements |

## 3. Work Item Management

Each work item represents an activity or deliverable related to the simulated student onboarding improvement initiative.

Items are organized according to:
- Description and expected outcome.
- Priority.
- Work item type.
- Current workflow status.

## 4. Work in Progress (WIP) Policy

The simulation adopts a WIP limit of two items in the In Progress column.

The purpose of this limit is to:
- Reduce excessive multitasking.
- Encourage focus on ongoing activities.
- Make work overload more visible.
- Support a more balanced workflow.

The WIP limit is a documented team policy. It is not configured as an automatic Jira restriction.

## 5. Workflow Rules

1. New ideas are registered in Idea.
2. Prioritized items move to To Do.
3. Work starts when an item moves to In Progress.
4. Items requiring validation move to Testing.
5. Completed items move to Done.
6. The team should review the WIP limit before starting additional work.

## 6. Continuous Improvement

The Kanban workflow supports continuous improvement through:
- Monitoring work distribution across columns.
- Identifying items that remain blocked or delayed.
- Reviewing priorities.
- Evaluating workflow bottlenecks.
- Adjusting work practices when necessary.

## 7. Project Snapshot

The Jira evidence included in this repository represents an intermediate snapshot of the simulated Kanban board.

It should not be interpreted as a final project completion report or as evidence of real organizational performance.

## 8. Disclaimer

This workflow was created for an independent portfolio simulation. All work items and scenarios are fictional. The WIP policy is documented as a proposed practice and does not represent an implemented organizational policy.
