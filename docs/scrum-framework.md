# Scrum Framework — Sprint 1 Documentation

## 1. Purpose

This document describes the Scrum practices applied in the simulated Student Onboarding Improvement project.

The objective is to demonstrate practical familiarity with Scrum concepts, backlog management, sprint planning, user stories, and sprint execution tracking using Jira.

## 2. Project Context

The simulation considers a fictional educational institution seeking to improve its student onboarding process.

The Scrum initiative focuses on understanding the current process, identifying potential pain points, and defining initial improvement requirements.

## 4. Sprint 1 — Discovery & Planning

**Sprint Goal:**

Understand the current student onboarding process, identify potential pain points, and define initial success criteria.

**Planned duration:** One simulated week.

### Sprint Backlog

Three items were selected for Sprint 1:

1. Map the Student Onboarding Journey.
2. Identify Student Onboarding Pain Points.
3. Define Onboarding Success Criteria.

## 5. User Stories and Acceptance Criteria

### US01 — Map the Student Onboarding Journey

**User Story**

As an operations team member, I want to map the student onboarding journey so that the main stages and interactions are clearly understood.

**Acceptance Criteria**
- Main onboarding stages are identified.
- The sequence of activities is documented.
- Relevant participants and responsibilities are identified.

### US02 — Identify Student Onboarding Pain Points

**User Story**

As an operations team member, I want to identify potential onboarding pain points so that improvement opportunities can be prioritized.

**Acceptance Criteria**
- Potential bottlenecks are documented.
- Issues are described clearly.
- Improvement opportunities are recorded.

### US03 — Define Onboarding Success Criteria

**User Story**

As an operations team member, I want to define onboarding success criteria so that process completion can be evaluated consistently.

**Acceptance Criteria**
- Completion criteria are documented.
- Required onboarding steps are identified.
- Criteria are clear and verifiable.

For this simulation, an item is considered Done when:
- Its requirements have been addressed.
- Acceptance criteria have been checked.
- Relevant documentation has been updated.
- The completed work is reflected on the Jira board.
